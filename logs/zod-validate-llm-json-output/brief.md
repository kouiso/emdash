## 上位記事を見たか

2026-10-31 に WebSearch で「LLM 出力 JSON zod safeParse エラー 検証 TypeScript」を検索し、結果のタイトルと要約だけを見た（本文は開いていない）。上位は英語の DEV Community の記事2本（Zod の検証と修復用のプロンプト、型安全な LLM の出力）、英語のガイド記事、日本語の記事1本（Zod v4 と Claude API の構造化出力）。要約で挙がっていたのは、`JSON.parse` のあとに `safeParse`、失敗時に `error.issues` をログに出す、エラーの内容をモデルに返して直させる、`z.prettifyError()`。この検索語は CSV の行ではなく、上位記事の傾向を見るために使っただけ。

差別化の判断:

- issues の中身を、`code` ごとに実際の出力で載せる（`invalid_type`、`invalid_value`、`unrecognized_keys`、`too_big`）。読む順（`path` → `code` → `message`）を最初に言い切る。
- Claude の Structured Outputs の公式ページを読み、`minimum`、`maximum`、`minLength`、`maxLength` に対応していないこと、`enum` の大文字小文字が保証されないことを根拠に、Structured Outputs を使っても zod の検証が要る理由を示す。
- `z.object` が余分なキーを黙って消すことを実行結果で示し、`z.strictObject` との使い分けの判断を書く。
- 英語のドキュメントでつまずく読者向けに、`ja` ロケールの出力も載せる。
