## C01 の1行

JS か TypeScript の経験があり、LLM の API をまだ本格的に呼んでいない人が、OpenAI API の料金をリクエスト前に見積もる方法を探したときに答える記事。

## 検索意図のタイプ

やり方（How-to）。読者が欲しいのは、料金の計算式と、トークン数を数えるコピペで動くコード。

## 上位記事を見たか

Google の検索結果そのものは見ていない。代わりに 2026-10-31 に WebSearch で「OpenAI API 料金 計算 トークン数 tiktoken JavaScript」を調べた。出てきたのは、入力と出力のトークン数に単価を掛ける計算式の解説、OpenAI のヘルプの「英語で1トークン≈4文字」の目安、Python の tiktoken を中心にした解説、js-tiktoken の `encodingForModel` を使う JavaScript への移植例、応答の usage で実数を見る話。JavaScript の情報は少なく、出力に推論トークンが入る話、出力の上限で料金の上限を出す話、js-tiktoken が新しいモデル名を知らない話は見当たらなかった。この記事はその3点と、手元の数と請求の数がずれる理由（OpenAI の Counting tokens のページ）を足す。

検索語は CSV が無いので未確定（`selection.md`、G10）。

## 書き手の態度（guides/03 不在1）

短い依頼文なら、入力を1トークン単位で数えても料金の上限はほとんど動かない。上限を決めるのは `max_output_tokens` で、入力を数える意味が大きいのは長い文書を渡すとき。js-tiktoken の `encodingForModel` に頼ると新しいモデル名で止まるので、エンコーディング名を直接書く。

## 読み終えた人ができるようになること

自分のプロンプトの入力トークン数を js-tiktoken で数え、モデルの単価と `max_output_tokens` から1回あたりと1か月あたりの料金の上限を出せる。手元の数がどこで請求とずれるかを知り、正確な数が要るときにトークン数の API を使う判断ができる。
